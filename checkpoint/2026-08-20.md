## 6. Deep re-audit: daily rollover + PR-PO-GRN-stock sync (found real bugs, prior claims did not fully hold)
Full detail: `agents/2026-08-20-stock-sync-deep-audit.md`. User explicitly asked to
not trust the earlier "100% verified"/"0 drift" claims and re-derive correctness.
3 parallel agents, disjoint file ownership. **4 genuine bugs found and fixed**, plus
2 double-PO/orphan-indent bugs:
- `master.js` `GET /materials/:id`: was using a narrow transaction_type whitelist
  instead of `!= 'opening'`, silently dropping returns/transfers/cash-purchases/
  adjustments/RTV/sales from the daily Opening/Received/Issued shown in
  `ProductDetailModal.jsx`. Fixed to match the other two endpoints.
- PR→PO conversion (`purchase.js` + `indent.js`): no guard against converting the
  same indent into two POs, or converting a non-Approved indent; cancelling a PO
  never reverted its linked indent's status (stuck forever). Both fixed. Also fixed
  a GST-double-application bug where `convert-to-po` inflated line totals by 18%
  versus every other PO-creation path in the codebase.
- `store.js` stock-sync: indent-issue was writing the ledger's `balance` as the
  pre-deduction stock value (off by the issued qty, systemically); warehouse
  transfer dispatch/receive routes wrote ledger rows but **never updated
  `materials.current_stock` at all** — the "0 drift" claim did not hold for
  transfers. Both fixed.

Several items correctly flagged as needing a product decision rather than
force-fixed (no GRN/inward idempotency guard against duplicate submits, PO-edit
not syncing back to source indent qty by design, an unused `approved_qty` column,
inconsistent privilege levels between the two PO-conversion routes).

## 7. Strict chain validation: Gate Pass, QC, AP Settlement (found the two most serious bugs of the day)
Full detail: `agents/2026-08-20-gatepass-qc-ap-settlement-audit.md`. User asked for a
strict validation of the whole PR→PO→GatePass→GRN→QC→AP-Settlement chain including UI
tabs, plus honest suggestions on process gaps. 3 parallel agents + 1 direct follow-up
fix. **7 real bugs found and fixed**:
- **Gate Pass**: dead edit UI (route existed, no button — added); missing permission
  guard on the edit route (any dept could edit — fixed); gate pass could be created
  against a Cancelled PO (fixed).
- **QC — most serious bug of the day**: GRN already applies the accepted/rejected
  split to stock at intake; `quality.js`'s inspection route then blindly re-applied
  the FULL quantity again on top — QC was double-counting stock and duplicating
  rejection records, not correcting anything. Fixed to diff against the existing
  decision and apply only the delta. Compounding bug: `Quality.jsx` never sent the
  GRN line-item id, so the backend update silently no-op'd on every real inspection —
  fixed. Also removed a fake-fallback that could submit a real QC decision against a
  fabricated line item when the real data failed to load.
- **AP Settlement — second most serious**: vendor bills had no server-side check
  tying the billed amount to the GRN's ACCEPTED (post-QC) value — added a 2%-tolerance
  guard in `finance.js`. Also fixed a join-fan-out inflating the AP Ledger tab's
  numbers, and a payments total computed over a paginated page instead of the full
  result set. Double-payment guard verified genuinely solid (row-locked).
- **Follow-up direct fix (purchase.js, outside any agent's file scope)**: the SAME
  billing bug existed in the actual live route the Purchase module uses to book bills
  (`POST /po/:id/bill`) — worse here, since `taxable_amount` silently defaulted to
  `po.total_value` (the full ordered value) whenever omitted. Fixed directly:
  taxable_amount now required, same GRN-accepted-value guard added.

Process gaps flagged, not force-fixed: gate pass not mandatory before GRN; QC not a
mandatory hold-back gate on current_stock; no maker-checker segregation between AP
bill-approval and payment-disbursement; dead duplicate RTV code path in security.js;
some gate-pass types defined but unreachable from the UI.
